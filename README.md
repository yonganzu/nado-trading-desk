# Nado Trading Desk

一个自托管的 Nado 永续合约多钱包工作台：批量管理钱包、自动登录注册、给钱包分角色、跑「自成交」刷量，并把每一笔成交的积分成本算清楚。

> **风险提示**：这个工具会**用真实资金、在真实市场下单**。私钥只在本地解锁后使用，请自己承担交易风险；默认主网参数下，任何一次运行前都会要求你手动输入 `RUN` 确认。

---

## 1. 启动

前置：Node.js ≥ 22.12、pnpm 11。

```bash
pnpm install
pnpm --filter console dev
```

打开 <http://127.0.0.1:18270>。

- **不需要 `.env`**：所有限制项都有默认值，开箱即用。
- 想收紧风控时可用环境变量覆盖（构建期内联，改完要重启）：
  `NEXT_PUBLIC_NADO_MAX_ORDER_NOTIONAL_USDT0`、`NEXT_PUBLIC_NADO_MAX_WALLET_USDT0`、
  `NEXT_PUBLIC_NADO_MAX_COHORT_USDT0`、`NEXT_PUBLIC_NADO_MAX_DEPOSIT_USDT0`、
  `NEXT_PUBLIC_NADO_MAX_REFUEL_ETH`。
- **网络切换**：左上角标题「Nado Trading Desk」右边有个「主网」按钮，点一下切网络；切回主网会弹确认框。
- 其它命令：`pnpm typecheck`、`pnpm test`、`pnpm --filter console build`。

## 2. Accounting：把账号纳入账本

入口：首页右上角的 **Accounting** 按钮（弹窗，右侧是账本明细）。

1. 打开后账本**自动加载**，并订阅公共 WS 的 `fill` 流，**逐笔实时记账**——正常情况下你不需要手动"导入"。
2. 想把开跑之前的成交也补进来：点 **Load history**，会按当前选中的子账户去拉 Nado 官方 indexer 的历史订单
   （**每个钱包最多 5000 条**，按 `submissionIndex` 游标逐页向前翻），
   按订单 `id` / 内容指纹**去重合并**（重复点不会算两遍）。
3. **Reload ledger** 重新读取本地账本文件；**Export CSV / Export JSON** 导出报表；**Reset ledger** 清空重来。
4. 面板底部的 **Net deposits（净充值）** 会按当前选中钱包拉取官方 indexer 的
   `deposit_collateral`（充值）与 `withdraw_collateral`（提币）事件，显示
   **净充值 = 充值 − 提币**、每个钱包的分项合计、以及逐笔明细（充值 +、提币 −）；
   点 **刷新净充值** 可手动重拉。

口径（表格里每一列都能对上）：

| 概念 | 算法 |
|---|---|
| 积分 | 挂单成交量 ÷ 16,000 + 吃单成交量 ÷ 2,500（美元/分） |
| Wear | 手续费 − 已实现盈亏（= 手续费 + 点差损耗） |
| 积分成本 | Wear ÷ 积分（每 1 分的净花费，越低越好） |
| 预计盈亏 | 积分 × 积分单价 − Wear |

说明：
- maker / taker 按成交回执标记；历史订单没有该字段时按手续费率反推（maker ≈ 1bp、taker ≈ 3.5bp），
  仍判不出来的会在表里显示 `(+n?)`。
- 某个钱包的成交要不要算进统计，用**钱包卡片右上角的眼睛按钮**切换：点成斜杠（`EyeSlash`）后，
  该钱包的成交就不再计入 Accounting 的 KPI、By wallet 表、积分成本折线图和导出（原始账本不受影响，
  随时可以再点回来）。选择按地址存在浏览器 localStorage，刷新后仍然有效。
- 面板里已不再显示 By cohort 汇总（挂单/吃单两组的量本来就对称）。

## 3. 在多网站上登录，并注册钱包

入口：首页右上角 **Accounts**（跳转 `/accounts`）。

### 3.1 先有账户和钱包

在 Accounts 页的保管库面板里：

1. 输入 **workspace password**（本地解锁用，不会上链）；
2. 三选一：
   - **Import + unlock**：用已有助记词导入一个 HD 账户；
   - **Generate N in-tab**：在当前标签页内新生成 N 个钱包；
   - **Import private keys**：直接粘贴一批私钥导入。
3. 派生出的钱包会按「账户（分组）」组织，后续注册/交易都按这个分组走。

> 私钥只在当前标签页内存里使用，不写进浏览器存储；但**请自行备份并保管好助记词**，丢了无法找回。

### 3.2 再批量登录 / 注册 Nado 官网

在 Accounts 页的「Nado 官网登录 / 注册」区块：

1. 选好**账户（分组）**；
2. 设 **登录钱包数量**（= 并发数，越大越快也越吃内存），建议先用 1 试一个；
3. 勾选 **跳过已注册**（断点续注册，已成功的钱包直接跳过）；
4. 点 **开始登录**。自动化会在后台开 Playwright 浏览器，逐个钱包完成：
   打开 `app.nado.xyz` → 点 Sign In → 用 MetaMask 完成 Privy 登录（**同一个弹窗即注册**）→
   同意条款 → 按序号设置用户名（`nado001`、`nado002`…）→ 跳过新手教程的 4 步 Skip；
5. 进度和结果看 **登录结果** 表（序号 / 地址 / 状态 / 耗时 / 错误）；中途可以 **停止注册**；
6. 想人工核对某个钱包：点该行的 **登录并查看**，会开一个已登录的 Chrome 窗口并保留约 2 分钟。

注册结果写进服务端登记表，**关掉页面、重启服务都不会丢**；首页钱包卡片上的「已注册」徽标就是从这张表回填的，
也可以用「检查 Nado 注册状态」重新逐个核对。

## 4. 选择分组、激活钱包

- **分组 = 账户**。首页顶部的 **Account 过滤器**勾选哪个账户，该账户的钱包就会出现在右侧钱包栏——
  这个勾选就是"激活"，会记在本地：新导入的账户默认自动勾选，你手动取消的勾选也会被记住。
- 只想要"某个账户里的几个钱包"参与：在过滤器里只勾那个账户，再在右侧钱包栏**逐个勾选**要参与的钱包。
- **分角色（Cohort）**：点左侧「Cohort」按钮，会把已勾选的钱包自动平衡地分成
  **挂单方（黄）** 和 **吃单方（蓝）**，并写进共享标签，刷新后仍然有效。
  也可以在右侧「挂单 / 吃单」板子里手动指定角色、手动一对一配对（`清空配对` 可重置）。
- 角色变化会**实时反映**到钱包卡片的标签上（包括开跑前余额检查自动互换角色的情况）。

## 5. 自成交平仓（核心功能）

左侧交易面板有两个标签：**Bulk action** 和 **自成交平仓**，本文只讲后者。

### 5.1 操作顺序

1. **Volume / pair (USDT0)**：填单笔名义额区间（例如 `100`–`105`）；
2. **Market**：选标的（只列支持 ≥20x 杠杆、且点差 ≥3 tick 的品种）。**会记住你上次选的标的**；
3. 在右侧勾选参与的钱包 → 点 **Cohort** 分成 maker / taker；
4. 点 **Run automation**（主网会弹确认框，需手动输入 `RUN`）；
5. **轮次**填 `0` = 一直跑到你点 Pause，填数字 = 跑够就停。
6. 日志框只看关键行；**逐对明细全量写进 `.data/automation.log`**，事后排查去翻文件。

### 5.2 每一轮做了什么

一轮对每个配对做 **4 条腿，全部自成交**：

| 阶段 | 挂单方（maker） | 吃单方（taker） |
|---|---|---|
| 开仓 | post-only 挂在内沿 tick | IOC 去吃它 |
| 平仓 | 上一轮的**吃单方**挂 reduce-only | 上一轮的**挂单方**去吃它 |

因为两条腿价格相同、互为对手，**全程不撞外部盘口，点差成本为 0**，而且自成交量翻倍。
理论成本只来自手续费：`2×maker(1bp) + 2×taker(3.5bp) = 9bp × 单笔名义额`，
50/50 的成交量配比下 **积分成本 ≈ 0.97 USDT0 / 分**。

### 5.3 开跑前与每轮开始前会做的事

1. **清仓**：开跑前把所有参与钱包的残留仓位先市价平掉（跑起来之前别急着 Pause）；
2. **角色平衡（默认关闭）**：曾实现「每一对里吃单方余额必须高于挂单方，否则互换」，
   但自成交每轮里同一个钱包各当一次 maker（开仓挂单）和一次 taker（平仓去吃），
   手续费同样是 1bp + 3.5bp，两侧费用与盈亏完全对称，**不需要按余额调换角色**。
   代码保留在 [roleBalance.ts](apps/console/app/lib/roleBalance.ts)，把 `ROLE_BALANCE_ENABLED` 改回 `true` 即可恢复。

### 5.4 日志怎么看

```
20:01:02.113 ▶ round 3 — makers buy                          ← 第 3 轮开始，方向
20:01:14.880 ▶ round 2 完成｜本轮盈亏 -0.0037 USDT0（不含手续费）  ← 上一轮结算（成交回执有延迟，放到下一轮开头结算）
20:33:00.371 ■ no pairs traded in 3 rounds — stopping.        ← 停止原因
```

「本轮盈亏（不含手续费）」= 参与钱包逐笔已实现盈亏的差值，**不含手续费**。
自成交本身在同价对敲下是 0，这一栏如果是负数，基本都是**平仓回退到市价**时吃掉的点差。

### 5.5 什么时候会自动停

- **连续 3 轮没有任何一对成交**（`■ no pairs traded in 3 rounds`）；
- **点差连续 5 轮不足 3 tick**：不会立刻停，先**自动换到点差更宽的其他标的**
  （日志 `⇄ 点差连续 5 轮不足 3 tick — 自动切换标的 A → B（当前点差 N tick）`，面板的 Market 选择框会同步更新）。
  挑的是支持 ≥20x 杠杆、当前点差 ≥3 tick 里最宽的那个；找不到合格标的就继续用原标的，再等 5 轮重试。
- **点差连续 60 轮不足**且一直换不到宽盘口（`■ 点差连续 60 轮不足 3 tick — stopping.`）——盘口太窄时挂在内沿会被抢，引擎选择不打；
- 你点 Pause（会先做收尾平仓）。

### 5.6 卡住了怎么处理

- 遇到 `429 Too Many Requests`：这是**按出口 IP** 的读令牌用完了（约 2 次/秒稳态）。引擎会自动退避重试，
  你也可以关掉多余标签页、少开钱包抽屉（抽屉会轮询盘口）。
- 仓位没平干净：在右侧打开该钱包的抽屉，点 **Close position** 手动平掉；
  或者再点一次 Run，开跑前的清仓会把它扫掉。
